# Workout Log UI/UX 全画面改善提案書

作成日: 2026-07-13  
対象: 現行の全画面・全主要操作  
方針: 現在のモノトーンで洗練された外観を保ち、説明書なしで初心者が迷わず記録できるユニバーサルデザインへ近づける。実装は本提案書の対象外。

## 1. 結論

現行デザインの静かさ、余白、モノトーン、カード表現は維持する価値が高い。一方で、ホームに「今日すること」と「過去の成果」が同じ強さで並び、記録導線にもコピー・編集・追加など複数の開始方法があるため、初心者は最初の一手を判断しなければならない。

改善の中心は次の3点とする。

1. ホームの主役を「今日のおすすめ部位」と「始める」の1アクションにする。
2. 履歴とホームのカレンダーを、常に現在月から開く・月曜始まり・同じ表記に統一する。
3. 「前回のメニューを丸ごとコピーする」導線を廃止し、前回値はセット入力時の参考情報としてだけ活用する。

目標とする最短導線は、`アプリを開く → 今日の部位を確認 → 始める → 種目を選ぶ → 重量と回数を入れる` である。

## 2. ユーザー指摘3点への回答

### 2.1 履歴が2025年7月など過去月から開く

通常は現時点の年月（監査日の場合は2026年7月）が最初に開くべきであり、現行挙動は不具合である。

原因は高い確度で、履歴の選択値が時刻を含む `Date()` である一方、ページのタグが各月の月初0時へ正規化された `Date` であることにある。SwiftUIのページ選択では両者が一致せず、25ページの中央にある現在月を選択できないため、先頭または不定のページが表示され得る。表示ヘッダーとページ内容が別月になる危険もある。

提案:

- 選択状態とページIDを `Date` の完全一致に依存させず、`YearMonth(year, month)` のような年月専用IDにする。
- 初期値は端末のカレンダー・タイムゾーンで算出した「今月」とする。
- 履歴タブを開き直した場合は原則現在月へ戻す。ユーザーが詳細画面から戻った直後だけは閲覧月を保持する。
- 月見出しを `2026-07` ではなく、日本語環境では `2026年7月` にする。
- 左右の月移動ボタンと「今日」ボタンを追加し、スワイプを知らない人でも移動可能にする。
- 受け入れ条件: 初回起動、タブ切替、日付変更直後、月末、年末年始、タイムゾーン変更後のすべてで正しい現在月が開く。

### 2.2 カレンダーが日曜始まり

本アプリ内には「今週」の集計や週開始日を月曜とするロジックがすでにあり、日曜始まりのカレンダーと不一致である。ホームと履歴は月曜始まりへ統一する。

提案:

- 曜日順を `月 火 水 木 金 土 日` に統一する。英字1文字は `T` が火曜・木曜で重複するため使わない。
- 余白計算も `Calendar.firstWeekday = 2` を使う共通カレンダー実装へ統一する。
- 「今週」の集計、ホーム、履歴、日別スワイプの週概念を同じカレンダー設定にする。
- 将来多言語対応する場合は、固定配列ではなくロケール由来の短縮曜日を月曜から並べ替える。
- 受け入れ条件: すべての月で1列目が月曜、7列目が日曜となり、日付位置と「今週」の件数が一致する。

### 2.3 「前回のメニューで始める」は不要

ローテーション運用と矛盾するため、ホームの「前回のメニューで始める」は削除する。同じ思想を徹底するなら、過去日詳細にある「今日にコピーして開始」も削除対象とする。

ただし、過去情報自体は入力負荷を下げるため有用である。丸ごと複製ではなく、種目詳細で「前回 60kg × 10回」の参照表示と、重量・回数の個別引き継ぎだけを残す。

代替するホームの主CTA:

- 見出し: `今日は「背中」`（次のローテーション部位）
- 補助文: `前回: 脚・3日前`
- 主ボタン: `背中のトレーニングを始める`
- 小さな副操作: `部位を変更`

初回だけは `最初の部位を選ぶ` を表示し、胸・背中・脚・肩・腕・体幹から選ぶ。2回目以降は、設定されたローテーション順と直近の完了記録から次の部位を自動提示する。提示は強制せず、1タップで変更可能にする。

## 3. 専門家別レビュー

### プロダクト設計

- アプリの中心価値を「詳細な分析」ではなく「迷わず記録を続けられること」と定義する。
- 1画面1目的を徹底する。ホームは開始、記録画面は入力、履歴は振り返り、種目は管理、設定は環境設定に限定する。
- 主要CTAは各画面1つにする。副操作はリンクまたはメニューへ格下げする。
- 完了の定義を明確にする。現状は入力値が即時保存される一方、ユーザーから見て「記録済み」と「入力中」の境界が分かりにくい。日別画面に明示的な `完了` を設け、完了後も `編集` で戻れるようにする。

### インタラクション／情報設計

- タップ可能なカードには同じ末尾シェブロン、選択には同じチェック、破壊操作には同じ赤と確認方法を使う。
- 横スワイプだけに機能を依存させない。履歴の月移動、日別の日付移動には見える前後ボタンを併設する。
- 「種目」「セット」「回数」「ボリューム」の同時表示は初心者には情報密度が高い。記録中はセット入力を優先し、集計は折りたたむか完了後に見せる。
- 長押しコンテキストメニューだけに「種目削除」を置かない。初心者が発見できる `…` メニューまたはスワイプ操作を併設する。

### ビジュアルデザイン

- 現行のモノトーン、システム背景色、16pt前後の角丸、控えめな境界線を維持する。
- 全カードに大きな影を付ける必要はない。階層が深く見えるため、通常カードは境界線のみ、主CTAや浮遊要素だけ影を使用する。
- IPAex明朝は個性がある一方、小サイズ・数字入力・英語混在で可読性が落ちやすい。ブランド見出しに限定し、本文・数値・ボタンはSan Franciscoまたは読みやすいゴシック系を推奨する。
- `Last record`、`reps`、`Notes`、`ALL`、`PR`、`1RM` などの混在を整理する。初心者向け表示は `前回の記録`、`回`、`メモ`、`すべて`、`自己ベスト`、`推定1RM` とする。専門用語は必要な場所で短い説明を添える。
- 今日、記録あり、選択中を同じ黒／グレーの濃淡だけで区別せず、形・線・アイコンも併用する。

### 初心者向けトレーニング設計

- 次の部位は直近の部位からローテーションで提案するが、疲労や予定に応じて変更できるようにする。
- 種目選択では部位を先に絞り、その部位の基本種目を3〜5件だけ上位表示する。全種目検索は二次導線にする。
- 種目追加時の一律3セット・10回は初心者には親切だが、意図が見えない。初期値として表示し、簡単に変更できることを示す。
- 推定1RMや総ボリュームは記録中の主情報にしない。成果画面・グラフに寄せる。
- 参考画像の外部検索は画像品質やフォームの正確性を保証できないため、将来は監修済み説明または信頼できる固定リンクを検討する。

### アクセシビリティ／ユニバーサルデザイン

- すべての操作領域を最低44×44ptにする。カレンダーの日付は見た目32ptでもタップ領域44ptを確保する。
- Dynamic Typeの最大サイズ、太字テキスト、表示ズーム、横向き、小型端末でレイアウトを確認する。固定列幅のセット行は特に崩れやすい。
- VoiceOverでは「7月13日、今日、記録あり、ボタン」のように状態まで読み上げる。曜日見出しも日本語で読み上げ可能にする。
- 色だけで状態を伝えない。記録日は点またはチェック、今日には枠、選択日には塗りを使い分ける。
- `フォームを確認` の外部遷移、削除、完了には明確なラベルと結果フィードバックを付ける。
- Reduce Motionが有効な場合はスプリング／ページ遷移を抑える。

### データ可視化

- 現行グラフはカテゴリで複数種目を合算した総ボリュームと、その日の全種目中最大の1RMを線で結ぶため、何が伸びたか解釈しにくい。
- 最初に `種目を選ぶ`、次に `推定1RM / 最大重量 / 総回数` を選ぶ構成にする。初心者には `ベンチプレスの推定1RM` のような具体名を表示する。
- X軸には文字列ではなく日付値を使い、期間を `1か月 / 3か月 / 1年` から選べるようにする。
- データが1件のときは折れ線でなく記録カード、0件のときは「種目を記録すると推移が表示されます」と次の行動を示す。
- 数値ラベルの常時全表示は重なりやすいため、選択点だけ詳細を表示する。

### 品質・信頼性

- 年月選択、週開始、タイムゾーン、日付境界のテストを追加する。
- 空のワークアウト、未来日の記録、複数のアクティブ記録、カスタム種目削除後の過去履歴を仕様化する。
- 全データ削除は「記録データ」と「カスタム種目／設定」のどこまで消すかを文言と処理で一致させる。
- 自動保存状態を明示し、保存失敗時はユーザーに知らせる。現行は一部エラーがコンソール出力だけである。

## 4. 全画面・全項目の改善提案

### 4.1 共通タブバー／ナビゲーション

現状: ホーム、履歴、種目、設定の4タブ。

提案:

- 4タブ構成は分かりやすく維持する。
- `種目` は閲覧より管理の意味が強いため、タイトルを `種目` に統一し、画面内の `種目ライブラリ` は必要なら説明文にする。
- タブを再タップしたとき、ホームは最上部、履歴は現在月、種目は検索解除・最上部へ戻る標準挙動を検討する。
- 各タブで大見出しの位置、余白、背景を統一する。ホームだけ英語の `Workout Log` を大見出しにする不統一は解消し、ブランド名は小さく、画面名または今日の日付を主見出しにする。

### 4.2 ホーム

現状項目: 月間カレンダー、今週回数、前回、ベスト更新、今日の記録、前回コピー／新規記録。

提案する表示順:

1. 今日の日付と次のローテーション部位
2. 主CTA `トレーニングを始める` または `続ける`
3. 今月の小型カレンダー
4. 今週回数・ベスト更新などの成果（必要なときだけ）

個別改善:

- `前回のメニューで始める` とコピー確認ダイアログを削除する。
- `新しく記録する` を主CTAにし、ローテーション部位をボタン名へ含める。
- 前回情報は `前回: 脚・3日前` の1行に圧縮する。
- 「今日はまだ記録がありません」は否定形なので、`今日のトレーニング` と次の行動を表示する。
- カレンダーカード全体のタップで履歴へ飛ぶことは見た目から分かりにくい。末尾に `履歴を見る` を表示するか、日付単位のタップにする。
- ホームカレンダーは月曜始まり、日本語曜日、記録日の明確なマーカー、今日の枠を採用する。
- ベスト更新が複数ある場合は最新1〜2件に絞り、`すべて見る` で履歴の該当グラフへ移動する。
- `前回` メトリクスが「昨日／○日前」で、ラベルも前回なのは理解できるが、記録が未来日または同日の場合に負数・0日前となる可能性を排除する。

### 4.3 履歴・カレンダー

現状項目: 部位フィルター、カレンダー／グラフ、年月、曜日、日付。

提案:

- 初期月不具合を最優先で修正し、年月を安定したIDで管理する。
- `ALL` を `すべて` に変更する。
- 曜日は `月 火 水 木 金 土 日` に統一する。
- 年月ヘッダーに `‹`、`›`、現在月以外では `今月` を表示する。
- 記録日は小さな点、選択日は塗り、今日は枠にして意味を分離する。現在の「今日も記録日も丸塗り」は判別しにくい。
- 記録のない日をタップするとホームの編集画面へ移動する挙動は、履歴閲覧中の意図を超える。空の日は無反応または `この日に記録を追加` の明示確認を出す。
- 記録のある日をタップしたときは、まず履歴内の日詳細を開く。編集は詳細内の明示ボタンにする。
- 月表示の高さ280pt固定は文字サイズや6週月で崩れる可能性があるため、内容に応じる。
- 過去12か月・未来12か月という無言の制限を撤廃するか、年月選択を用意する。少なくとも最古記録まで遡れることを保証する。

### 4.4 履歴・グラフ

現状項目: 総ボリューム、最大推定1RM、部位フィルター。

提案:

- 「部位」ではなく最初に「種目」を選ぶ。部位フィルターは種目選択を短くする補助とする。
- グラフタイトルに対象を明記する。例: `ベンチプレス・推定1RM`。
- 総ボリュームと推定1RMを初心者向けの短い説明付きで切り替える。
- 自重種目は重量0相当のグラフにせず、最大回数または総回数を使う。
- 点の日付・値はタップ時に表示する。軸・単位・期間を明示する。
- グラフから該当日の記録詳細へ遷移できるようにする。

### 4.5 日別記録画面

現状項目: 4指標、種目一覧、種目追加、過去日コピー、全削除、左右日付スワイプ。

提案:

- 画面上部を `7月13日（月）` と `今日` のような自然な日付にする。
- 日付の左右ボタンと日付ピッカーを用意し、スワイプを補助操作にする。
- 記録中は指標4つを1行で常時表示せず、`2種目・6セット` 程度に圧縮する。ボリュームは完了後に表示する。
- 主CTAは状態で変える。空なら `種目を追加`、入力中なら `記録を完了`、完了済みなら `編集`。
- 過去日の `今日にコピーして開始` を削除する。
- `この日の記録をすべて削除` は常時本文に置かず、右上 `…` の中へ移動する。
- 種目削除を長押しだけにせず `…` またはスワイプで発見可能にする。
- 未来日の空画面で記録できるかを明確にし、許可するなら `予定` と `実績` を混同しない。

### 4.6 種目選択

現状項目: 検索、部位チップ、全種目リスト、追加ボタン、参考画像、カスタム追加。

提案:

- ローテーション部位で開いた場合、その部位を初期選択し `おすすめ` を上位3件にする。
- 行全体タップと行内の `追加` が同じ動作で重複しているため、チェック式の複数選択にし、下部固定ボタン `2種目を追加` で確定する。1件ずつ閉じて開き直す反復をなくす。
- 既に当日の記録へ追加済みの種目はチェック済みまたは非活性にし、重複追加を防ぐ。
- `カメラ` アイコンは参考画像検索を連想しにくい。`フォーム` というテキスト付き副操作にする。
- 検索結果0件では `「○○」は見つかりません` と `カスタム種目として追加` を表示する。
- カスタム追加の `+` は意味が曖昧なので `新しい種目` のテキストを併記する。

### 4.7 種目詳細／セット入力

現状項目: 休憩タイマー、前回記録、セット表、重量・回数ピッカー、推定1RM、メモ、各値コピー、削除、セット追加、フォーム検索。

提案:

- 最重要画面として、1セットを `セット番号 | 重量 | 回数 | 完了チェック` の4要素に絞る。
- 推定1RMは行から外し、種目全体の成果として下部または完了後に表示する。
- ゴミ箱を各行に常時置くと誤操作と視覚ノイズが増える。スワイプ削除または `…` にする。
- `rep`、`Last record`、`Notes` を `回`、`前回の記録`、`メモ` に統一する。
- 重量は1kg刻みだけでなく、0.5kg刻みやジム環境に応じた刻み幅を設定できるようにする。lbs表示時に内部kgを1kg刻みで変換すると不自然な2.2lbs刻みになるため、表示単位に応じた入力刻みにする。
- ホイールを毎回開くより、数値キーボード＋増減ボタンの方が反復入力に速い。前回値を初期値として薄く提示し、入力または1タップ採用にする。
- 重量・回数・メモにそれぞれコピーアイコンを置く構成は複雑。新しいセットは直前セット値を自動継承し、変更したい項目だけ編集する。
- 休憩タイマーはセット完了チェックで自動開始し、通知・触覚で終了を知らせる。手動開始も残す。
- タイマーは画面遷移でリセットせず、トレーニング中は継続表示する。
- 自重種目では重量欄を `自重` とし、必要なら追加重量だけ別入力にする。

### 4.8 過去記録詳細

現状項目: 統計カード、編集、今日へコピー、種目別セット。

提案:

- `今日にコピーして開始` を削除する。
- 主操作を `記録を編集` 1つにする。誤って編集状態にした場合に完了状態へ戻せるようにする。
- 統計は色付きアイコンを使わず現行モノトーンへ統一する。
- 種目ごとに前回比または自己ベストだけを小さく表示する。すべての数値を強調しない。
- 同じ役割を持つ `DayWorkoutView`、`DayDetailView`、`WorkoutDetailView` の体験を統合し、閲覧と編集の遷移を一貫させる。

### 4.9 種目タブ

現状項目: 検索、部位チップ、カテゴリ別一覧、PR、カスタム追加・削除。

提案:

- 各種目行のタップ先として、説明・対象部位・履歴・自己ベストをまとめた種目詳細を用意する。現在は行が情報表示だけで、タップ可能性が不明確である。
- `PR` は `自己ベスト` とし、最高重量だけでなく自重種目は最大回数に切り替える。
- 履歴のない種目に `未記録` を薄く表示すると、右側が空白である意味が分かる。
- カスタム種目削除時、過去記録への影響を確認文に明示する。使用中の種目は削除でなくアーカイブを推奨する。
- カスタム種目追加画面は種目選択内と種目タブ内で共通化し、入力値リセット・重複名チェック・カテゴリ必須を統一する。

### 4.10 設定

現状項目: 累計記録、kg/lbs、バージョン、開発者、全データ削除。

提案:

- 累計統計は設定ではなく履歴またはプロフィール相当の情報である。設定画面は設定だけに絞る。
- `ローテーション` セクションを追加し、部位順の並べ替え、休養日の扱い、提案のオン／オフを設定できるようにする。ただし初期設定は不要で、標準順をすぐ使えるようにする。
- `トレーニング` セクションに重量単位、重量刻み、既定セット数、休憩時間をまとめる。
- `アクセシビリティ` として触覚・自動タイマーなどを用意する。文字サイズはシステム設定へ従う。
- データ管理にエクスポート／バックアップ方針を追加する。全削除だけでは安心感がない。
- `全データを削除` の対象を明記し、確認ではボタンを2段階にするか、対象件数を表示する。削除完了のフィードバックも必要。
- 開発者名が仮表記なら正式名称へ変更し、プライバシーポリシー、問い合わせ、ライセンスを追加する。

### 4.11 カスタム種目追加

- 画面タイトルを `種目を追加` に短縮する。
- 種目名入力へ初期フォーカスし、キーボードの完了操作を提供する。
- `対象筋肉（任意）` は初心者には判断が難しいため、カテゴリから自動設定し、必要な人だけ `詳細設定` で変更する。
- 同名種目がある場合は既存種目を提示し、重複を避ける。
- 追加後は「追加しました」を触覚と短い表示で知らせ、呼び出し元ではその種目を選択済みにする。

### 4.12 1RM計算機

現行コードには画面があるが、主要導線から見つけにくい。

提案:

- 初心者向け主導線から外し、種目詳細または設定の補助ツールへ置く。
- `1RM` の意味と「推定値であり、安全に1回最大へ挑戦する指示ではない」ことを短く表示する。
- 重量入力は現在の単位と自然な刻み幅に合わせる。
- 使用しないならコードと体験の複雑性を減らすため削除候補とする。

### 4.13 ダイアログ、空状態、エラー

- 確認ダイアログは破壊操作と大きな状態変更だけに使う。通常の開始・編集では不要。
- 空状態は「ない」だけで終わらず、1つの次行動を置く。
- 保存失敗、データ読み込み失敗、外部検索を開けない場合はユーザー向けエラーを表示する。
- `Notes` をコピーする等、内部用語や英語をすべて自然な日本語へ統一する。

## 5. 推奨する新しい情報設計

### ホーム

`今日のおすすめ部位 → 始める／続ける → 今月の記録 → 最近の成果`

### 記録

`部位確認 → 種目を複数選択 → セット入力 → 完了 → 短い成果表示`

### 履歴

`現在月カレンダー → 日の詳細` または `種目選択 → 推移グラフ`

### 種目

`検索／部位 → 種目詳細 → 過去記録・自己ベスト`

この構造なら、初心者はホームの主ボタンだけを追えば記録でき、上級者は履歴・種目から詳細へ進める。

## 6. 優先順位

### P0: 信頼性と方針の矛盾を解消

1. 履歴を必ず現在月から開く。
2. 全カレンダーを月曜始まりに統一する。
3. ホームと過去日から「今日へコピー」を削除する。
4. 記録のある日タップは履歴詳細、空の日タップは明示的な追加導線に分ける。
5. 日本語／英語表記と `kg/lbs` 入力刻みの不整合を直す。

### P1: 初心者の最短導線を作る

1. ホームにローテーション部位と単一の開始CTAを置く。
2. 種目を部位で初期絞り込みし、複数選択でまとめて追加する。
3. セット行を重量・回数・完了に簡素化する。
4. 明示的な「記録を完了」を追加する。
5. 見える日付移動、種目削除、現在月復帰を用意する。

### P2: 継続と振り返りを改善

1. 種目単位で意味のあるグラフへ再設計する。
2. 種目詳細と自己ベスト表示を追加する。
3. タイマーの自動開始・継続表示を整える。
4. ローテーション設定、重量刻み、既定セット数を設定へ追加する。

### P3: 品質の仕上げ

1. Dynamic Type、VoiceOver、Reduce Motion、コントラストを全画面検証する。
2. エクスポート／バックアップ、エラー表示を整える。
3. 文言、触覚、アニメーション、カードの影を統一する。

## 7. 成功指標

- 初回ユーザーの80%以上が説明なしで2分以内に最初の1セットを記録できる。
- アプリ起動から記録開始まで通常1タップ、部位変更時でも3タップ以内。
- セット追加後、重量・回数の入力または確認が各1タップ以内。
- 履歴を開いた際の誤月表示が0件。
- 月曜始まりと「今週」集計の不一致が0件。
- VoiceOverだけで、トレーニング開始・種目追加・セット入力・完了・履歴確認が可能。
- 誤削除、空記録、意図しないコピーの発生率を計測し、限りなく0へ近づける。

## 8. 検証計画

- 5名以上の筋トレ記録アプリ未経験者へ、説明なしで「背中の日を記録してください」と依頼する。
- 観察項目は、最初のタップ、迷った時間、戻る回数、誤操作、完了を認識できたかとする。
- 端末条件は小型iPhone、標準iPhone、大型文字、ダークモード、VoiceOverを含める。
- 日付条件は月初、6週表示月、年末年始、タイムゾーン変更、端末日付変更を含める。
- P0完了後に再テストし、ユーザーが文言を読まなくても視覚階層だけで操作できるかを確認する。
