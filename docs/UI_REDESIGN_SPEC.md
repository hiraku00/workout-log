# Workout Log UI/UX リデザイン設計書

## 1. 文書情報

- 対象アプリ: Workout Log
- 対象OS: iOS 26以降 / iPhone
- UIフレームワーク: SwiftUI
- 設計方針: Appleの標準UIに調和する、静かで精密なトレーニング記録体験
- 実装方針: 現在の機能・画面遷移・SwiftDataモデルを維持し、視覚設計と操作性を刷新する
- 本書の役割: 別工程の実装者が、追加のデザイン判断を最小限にして実装できる仕様書

## 2. 目的

Workout Logの機能は維持したまま、画面ごとに分散している見た目と操作ルールを統一する。装飾による高級感ではなく、情報の優先順位、余白、文字組み、操作の予測しやすさによって、デザイン事務所が設計したような完成度を目指す。

達成したい状態は次のとおり。

1. 開いた瞬間に「今日何をするか」が分かる。
2. トレーニング中は入力に集中でき、誤操作が起きにくい。
3. 履歴では成果と傾向を短時間で読み取れる。
4. どの画面でも、同じ役割の要素が同じ見た目・挙動になる。
5. ライトモード、ダークモード、文字サイズ変更でも品質が崩れない。

## 3. 現状評価

### 3.1 維持する長所

- ホーム、履歴、種目ライブラリ、設定の4タブ構成
- 日付単位のワークアウト管理と左右スワイプ移動
- セット重量・回数・推定1RM・休憩タイマーの入力機能
- カテゴリ絞り込み、検索、カスタム種目追加
- 履歴カレンダーとグラフ表示
- SwiftDataを使った既存データモデル
- SF Symbolsとシステムカラーを中心にしたiOSらしい基礎

### 3.2 解決する課題

- 画面によって背景色、カードの角丸、枠線、影、ボタン高さが異なる
- 統計値が小さなカードに分割され、主要情報と補助情報の差が弱い
- 英語と日本語のラベルが混在し、一部に `Calender` の表記揺れがある
- カテゴリ色とアクセント色の使い方に共通ルールがない
- 主要操作と補助操作が似た外観になり、優先順位が伝わりにくい
- 空状態が機能説明中心で、次の操作への誘導が弱い
- 小さい画面やDynamic Typeで、横並び統計とセット入力列が窮屈になる可能性がある
- カードが多く、情報のまとまりではなく「すべて囲う」構成になりやすい

## 4. デザイン原則

### 4.1 Quiet Precision

トレーニングの数値が主役。背景や装飾は抑え、重量、回数、日付、進捗が最も強く見えるようにする。

### 4.2 One Primary Action

1画面内で最も重要な操作は原則1つだけ強調する。その他はセカンダリ、テキスト、メニューへ段階を下げる。

### 4.3 Native First

NavigationStack、TabView、List、Form、Picker、confirmationDialog、searchableなど、iOS標準挙動を優先する。独自UIは情報提示や操作効率が明確に向上する場合だけ使用する。

### 4.4 Progressive Disclosure

日常的に使う情報を最初に見せ、低頻度の編集・詳細設定はコンテキストメニュー、スワイプ、シートに配置する。セット削除はトレーニング中の入力訂正として頻度が高く、対象行のゴミ箱を直接操作できるようにする。

### 4.5 Motion with Purpose

アニメーションは状態変化の理解を助ける用途に限定する。常時動く装飾や大きなバウンドは使用しない。

### 4.6 Apple公式HIGに基づく実装判断

本アプリでは、Apple公式の[iOS設計ガイド](https://developer.apple.com/design/human-interface-guidelines/designing-for-ios)と[デザイン原則](https://developer.apple.com/design/human-interface-guidelines/design-principles)を、操作と情報配置の判断基準にする。独自のデザイン技能や特定の外部デザインを参照元にしない。

- **Purpose / Simplicity**: 画面の主目的である記録入力を最短経路にする。意味の説明を要する記号や、入力を狭める装飾アイコンは置かない。背景のグラデーション、常時表示するガラス表現、過剰な影は使用しない。
- **Familiarity**: `NavigationStack`、`TabView`、`List`、`Form`、`Picker`、システムシート、SF Symbols、標準のタブバーを優先し、標準と異なる外観のグローバル上書きは行わない。
- **Flexibility**: `systemBackground`、`systemGroupedBackground`、`secondarySystemGroupedBackground`、`tertiarySystemFill`、`primary`、`secondary` をトークン化して使う。固定ライトモードや固定RGB色を避け、Dark Mode、Dynamic Type、コントラスト設定に適応する。
- **Materials / Liquid Glass**: 標準のタブバーに任せ、カスタムの主要操作と休憩タイマー操作だけに `glassEffect` を適用する。入力表・履歴・一覧などのコンテンツ層にガラス材質を重ねない。
- **Agency / Responsibility**: 削除には誰もが理解できるゴミ箱を使い、対象セットと同じ行の完了の直後に置く。入力済みセットのみが集計・前回記録に反映され、誤操作時にも対象を取り違えないよう、操作対象とボタンを近接させる。
- **Grouping & mapping**: 見出し、入力行、前回記録、ワークアウト一覧は同じ列順（セット / 重量 / 回数 / 1RM / 完了 / 削除）を使う。列を追加・削除しても、重量・回数・1RM の左端と右端は変えない。
- **Craft**: 数値の桁数から列幅を決める。iPhone標準幅では重量を `999.9 kg`、回数を `99 回`、1RMを `999.9` まで読める幅とし、残りの余白を任意に広げない。数値は右揃えと等幅数字で比較しやすくする。
- **Feedback**: 完了、削除、タイマー終了など意味のある確定点だけに触覚・音・状態色を使う。押下フィードバックは短く控えめにし、装飾目的の常時アニメーションは置かない。

休憩タイマーは終了予定時刻を基準にし、対応OSをiOS 26以降とする。AlarmKitが許可・登録できた場合はOS管理アラームを使い、未許可または登録失敗時はtime-sensitiveローカル通知へフォールバックする。通知側の表示・音はユーザーの通知設定および集中モードに従う。前面表示中は通知バナーを抑止し、同梱アラーム音とアプリ内の「休憩終了」アラートを表示する。AlarmKitはOSの仕様により再生中の音楽や動画を中断する場合があり、アラーム停止後の再開判断は音声を再生していたアプリ側が行う。本アプリから他社アプリの再生を再開する公開APIはないため、自動再開は行わない。読み上げは使わない。

推定1RMはEpley式 `重量 × (1 + 回数 / 30)` またはO’Conner式 `重量 × (1 + 回数 × 0.025)` を設定画面で選択する。これは比較用の推定値であり、実測の最大挙上重量ではない。式が異なるアプリとは値が一致しない場合がある。

この原則に反する変更は、画面単体で成立していても採用しない。特に「他画面との列ズレ」「アイコンの意味が文脈から分からない」「数値入力を圧迫する余白」はデザイン上の不具合として扱う。

## 5. 情報設計

### 5.1 タブ構成

| タブ | 表示名 | SF Symbol | 主目的 |
|---|---|---|---|
| 0 | ホーム | `house` / `house.fill` | 今日の開始、直近状況の把握 |

タブ名は短い日本語に統一する。選択中のみ塗りつぶしシンボルを使用し、タブバーのアクセントは `primary` を基本とする。

### 5.2 用語統一

| 現在の表現 | 採用表現 |

| Today's training | 今日のトレーニング |
| Training load/7days | 7日間 |
| Training load/28days | 28日間 |
| Total load | 累計 |
| Calender | カレンダー |
| Graph | グラフ |
| EXERCISES | 種目 |
| SETS | セット |
| REPS | 回数 |
| VOLUME | ボリューム |

数字の単位は値に近接させる。例: `72.5 kg`、`10 回`、`12.4 t`。画面内で日本語と英語を装飾目的に混在させない。

## 6. デザインシステム

### 6.1 カラー

固定RGB色を画面へ直接記述せず、セマンティックトークンを介して使用する。

| Token | Light | Dark | 用途 |
|---|---|---|---|
| `background` | `systemGroupedBackground` | 同セマンティック色 | 画面背景 |
| `surface` | `secondarySystemGroupedBackground` | 同セマンティック色 | リスト・軽いまとまり |
| `surfaceElevated` | `systemBackground` | 同セマンティック色 | カード、モーダル内強調領域 |
| `fillSubtle` | `tertiarySystemFill` | 同セマンティック色 | 入力、非選択コントロール |
| `textPrimary` | `primary` | `primary` | 見出し、値、本文 |
| `textSecondary` | `secondary` | `secondary` | ラベル、説明 |
| `separator` | `primary.opacity(0.08)` | `primary.opacity(0.12)` | 境界線 |
| `accent` | `primary` | `primary` | 主要操作、選択状態 |
| `success` | `systemGreen` | `systemGreen` | 完了、達成 |
| `warning` | `systemOrange` | `systemOrange` | 注意 |
| `destructive` | `systemRed` | `systemRed` | 削除のみ |

カテゴリ色はグラフの識別と小さなインジケータに限定する。大面積の背景や主要ボタンには使わない。色だけで状態を伝えず、アイコン、ラベル、形状を併用する。

### 6.2 タイポグラフィ

外部フォントは追加せず、San Franciscoを使用する。数字は `.monospacedDigit()`、大きな成果数値のみ rounded designを許可する。

| Style | SwiftUI基準 | Weight | 用途 |
|---|---|---|---|
| Screen Title | `.largeTitle` | bold | Navigation title |
| Section Title | `.title3` | semibold | 画面内の主要セクション |
| Card Title | `.headline` | semibold | カード・種目名 |
| Body | `.body` | regular | 本文、主要ラベル |
| Supporting | `.subheadline` | regular/medium | 補足、行の副情報 |
| Caption | `.caption` | regular/semibold | 単位、期間、メタ情報 |
| Metric Hero | 40pt rounded | bold | 1RMなど単一の主要値 |
| Metric | `.title2` | semibold/bold | 集計値 |

独自の文字サイズはMetric Hero以外では原則使用しない。文字間隔は0。英字の全大文字を小見出し用途に常用しない。

### 6.3 スペーシング

4ptグリッドを採用する。

| Token | 値 | 用途 |
|---|---:|---|
| `space1` | 4 | ラベルと値の密接な間隔 |
| `space2` | 8 | アイコンとテキスト、行内 |
| `space3` | 12 | 関連要素間 |
| `space4` | 16 | 標準余白、画面左右余白 |
| `space5` | 20 | カード内の広い余白 |
| `space6` | 24 | セクション間 |
| `space8` | 32 | 大きなセクション間 |

画面左右余白は16ptを標準とし、カード内は16pt、主要カードのみ20ptを使用する。

### 6.4 角丸・枠線・影

| 対象 | 角丸 | 枠線 | 影 |
|---|---:|---|---|
| 小型入力・セグメント内選択 | 8 | 任意 | なし |
| ボタン・小型タイル | 12 | 0.5pt | 原則なし |
| 標準カード | 16 | 0.5pt | なし |
| ヒーローカード | 20 | 0.5pt | Lightのみごく薄く |
| チップ | Capsule | 0.5pt | なし |

影は `black.opacity(0.04)`, radius 12, y 4を上限とし、カード階層を示す必要がある箇所だけに使う。ダークモードでは影より枠線を優先する。

### 6.5 アイコン

- SF Symbolsのみ使用する。
- 行内アイコンは16-18pt、主要アクションは18-20pt。
- タップ領域は最低44 x 44pt。
- アイコン単独ボタンにはaccessibilityLabelを必須とする。
- 装飾アイコンを増やしすぎず、操作・カテゴリ・状態の識別に限定する。

### 6.6 モーションと触覚

- 押下: scale `0.98`、0.15-0.22秒。
- 選択切替: easeInOutまたはspring、0.20-0.28秒。
- 画面内データ更新: opacityと数値変化を中心にし、大きな移動は避ける。
- Reduce Motion有効時はscaleとspringを無効化または単純なcrossfadeへ変更する。
- 種目追加、セット追加: light impact。
- ワークアウト保存、コピー完了: success notification。
- 削除確認前には触覚を発生させず、確定後のみwarningまたはsuccessを使用する。

## 7. 共通コンポーネント仕様

### 7.1 AppCard

- 背景: `surfaceElevated`
- 角丸: 16pt、ヒーロー用途のみ20pt
- 内側余白: 16pt
- 枠線: `separator`, 0.5pt
- カード全体が押せる場合は、内部の一部だけではなく全領域をcontentShapeにする
- カード内に別のカードを入れない。階層はDivider、余白、背景差で表現する

### 7.2 PrimaryButton

- 高さ: 50pt以上
- 背景: `accent`
- 前景: `systemBackground`
- 角丸: 12pt
- ラベル: SF Symbol + 動詞を含む短い文言
- disabled: opacity 0.35、押下アニメーションなし
- 1画面に原則1つ

### 7.3 SecondaryButton

- 高さ: 48pt以上
- 背景: `surfaceElevated`
- 前景: `textPrimary`
- 枠線: `separator`, 0.5pt
- 主要ボタンより視覚的に弱くする

### 7.4 IconButton

- 可視サイズ: 32-36pt、タップ領域: 44 x 44pt
- 背景は原則なし。強調が必要な場合のみ円形の`fillSubtle`
- 削除は通常状態で赤くせず、破壊的操作の確定UIでのみ赤を使う

### 7.5 FilterChip

- 高さ: 34pt以上
- 横余白: 12pt
- 選択: `accent`背景 + 反転文字
- 非選択: `surfaceElevated`背景 + 0.5pt枠線
- 横スクロール時、先頭・末尾に16ptの余白を維持
- 選択状態をVoiceOverへ通知する

### 7.6 MetricGroup

- 3-4個の値を別カードへ分割せず、1つのsurface内で均等配置する
- 値: `.title2`, semibold, monospacedDigit
- ラベル: `.caption`, secondary
- 区切り: 高さ32-40ptのDivider
- Dynamic TypeのAccessibilityサイズでは2列グリッドまたは縦並びへ切り替える

### 7.7 EmptyState

- 高さの中央付近に配置
- シンボル: 40-48pt、secondary
- タイトル: `.headline`
- 説明: `.subheadline`, secondary、最大2行
- 次に行う操作がある場合はSecondaryButtonを1つ置く
- 機能説明や操作手順を長文で表示しない

### 7.8 ListRow

- 最小高さ: 60pt
- 先頭アイコン: 36-40ptの円形領域
- 主ラベル: `.body`または`.subheadline`, medium
- 副ラベル: `.caption`, secondary
- 右側の数値はmonospacedDigit
- 行全体の選択と、右側の独立アクションのタップ領域を重ねない

### 7.9 セット表（入力・前回記録・一覧）

- 列順は `セット / 重量 / 回数 / 1RM / 完了 / 削除` に固定する。
- 一覧・前回記録の基準幅は順に `24 / 78 / 48 / 56 / 32 / 32pt`、入力の基準幅は `24 / 120 / 66 / 56 / 32 / 32pt` とする。入力の重量・回数列にはコピー・自重操作を含める。余った横幅は列間へ均等に配分し、広い端末で重量欄だけが肥大しないようにする。
- 入力画面では、完了チェックボックスの右隣にゴミ箱を置く。メモ欄に削除・完了・重量の操作を混在させない。
- 重量はdecimalPadで小数を直接入力する。自重は重量欄内右端の専用ボタンで切り替え、選択中は「解除」を表示する。重量・回数は、2セット目以降に上のセットの値を個別コピーできる。追加セットは直前の重量とメモのみ継承し、回数は10から始める。
- 完了は入力行の右端に置き、削除は完了チェックボックスの直後に置く。メモ欄右端には上セットのメモコピーがある場合だけコピー操作を置く。
- メモ欄の左端はセット番号ではなく重量欄の左端に揃える。セット番号を独立した縦の目印として残し、セット間の区切りを読み取りやすくする。
- 前回記録は同じ最初の4列位置を使用し、未完了の `0 kg` プレースホルダーは表示・集計しない。
- 一覧も入力画面と同じ列定義を使い、各セットの右端で削除できる。種目カードの開く操作とセット削除のタップ領域は重ねない。

## 8. 画面別仕様

### 8.1 ホーム

#### 目的

今日のトレーニングを開始し、直近の継続状況と負荷を一目で確認する。

#### 構成

1. Large Navigation Title `Workout Log`
2. 「今日のトレーニング」主要アクション
3. 今月のミニカレンダー
4. トレーニング負荷のMetricGroup

#### レイアウト

- 縦1列を基本とする。カレンダーと負荷カードの固定幅横並びは廃止する。
- 今日のトレーニングを最初のカードに置き、日付と現在の状態を表示する。
- 当日記録なし: `plus`、文言「今日のトレーニングを記録」
- 当日記録あり: `checkmark.circle.fill`、種目数・セット数を表示し、文言「今日の記録を続ける」
- カレンダーは月名、前後移動は持たず、タップで履歴タブへ移動する。
- 記録日は日付下部の3ptドット、今日の日付は塗りつぶし円で表現する。
- 負荷は「7日間」「28日間」「累計」を1つのMetricGroupにまとめる。

#### 受け入れ条件

- 主要操作がスクロールせず表示される。
- 320pt幅でもカレンダーの日付が欠けない。
- 数値が1000tを超えてもレイアウトが変形しない。

### 8.2 日別ワークアウト

#### 目的

対象日の種目一覧を把握し、種目追加またはセット入力へ最短で進む。

#### 構成

1. Inline Navigation Titleに日付
2. 統計MetricGroup
3. 種目リスト
4. 「種目を追加」SecondaryButton
5. 削除操作は下部のテキストボタンまたはメニュー

#### レイアウト・操作

- 左右スワイプによる日付移動は維持する。
- 統計4項目は1つのsurfaceにまとめる。
- 種目カードは種目名、完了セット数、固定列の全セット表を表示する。各セットは表の右端から直接削除できる。
- カード右上の上下chevronで種目順を変更し、ゴミ箱から種目と配下の全セットを確認後に削除する。
- 空状態は「この日の記録はありません」と「種目を追加」を表示する。
- 全削除は常時目立たせず、`ellipsis`メニューまたは最下部のdestructive textへ移す。

### 8.3 種目詳細・セット入力

#### 目的

トレーニング中に片手で、重量と回数を少ない操作で入力する。

#### 構成

1. 種目名 / フォーム確認
2. 休憩タイマー
3. 前回記録
4. セット入力表
5. セット追加

#### 休憩タイマー

- 1つの横長surfaceとして表示する。
- 左: `timer`アイコンと「休憩」
- 中央: `MM:SS`、title2、monospacedDigit
- 右: play/pauseのIconButton
- 時間変更は中央値タップでMenuまたはPickerを開く。
- 実行中はアクセント色を小さなインジケータにだけ使用する。
- `safeAreaInset`で上部に固定し、セット表をスクロールしても常に表示する。
- 前回記録は完了済みセットのみを同じ固定列のコンパクト表で表示し、履歴画面へのリンクを置く。

#### セット入力

- 列: セット番号 / 重量 / 回数 / 推定1RM / 完了 / 削除。
- 重量・回数は44pt以上の入力領域とし、重量は小数を直接入力、回数はホイールPickerで1〜50回から選ぶ。
- 完了セットだけを集計と前回記録に反映する。削除は完了の直後のゴミ箱、補助導線としてスワイプからも実行できる。
- メモ欄は常に任意入力として表示し、左端を重量欄に揃える。

#### レスポンシブ

- 320-374pt幅では推定1RMの列ラベルを`1RM`とし、値をcaptionへ縮小する。
- Dynamic TypeのAccessibilityサイズでは表形式をやめ、セットごとの縦レイアウトへ切り替える。

### 8.4 種目選択

#### 目的

検索またはカテゴリから、目的の種目を素早く選ぶ。

#### 仕様

- Navigation Titleは「種目を選択」、検索は標準searchableを維持。
- カテゴリチップは検索欄の下に固定し、横スクロールする。
- 行にはカテゴリシンボル、種目名、対象筋を表示する。
- 行タップで即追加して閉じる既存挙動を維持する。
- カメラ操作は意味が伝わりにくいため、`photo.on.rectangle`または`figure.strengthtraining.traditional`を使い、アクセシビリティ名を「フォーム画像を検索」にする。
- フォーム画像は種目名と「正しいフォーム」でGoogle画像検索を開く。Braveが利用可能な場合はGoogleアプリのUniversal Linkを避けてBraveへURLを渡し、利用できない場合は通常のHTTPS URLを開く。
- カスタム種目追加は右上のplusからシート表示する。
- 検索結果0件では「該当する種目がありません」と「カスタム種目を追加」を表示する。

### 8.5 履歴

#### 目的

過去の実施日を探し、トレーニング量の傾向を理解する。

#### 構成

1. カテゴリFilterChip
2. 「カレンダー / グラフ」セグメント
3. 選択ビュー

#### カレンダー

- 月切替は左右chevron、中央に`yyyy年M月`。
- 今日、選択日、記録日をそれぞれ形状で区別する。
- 日付セルは最低40 x 40ptのタップ領域を確保する。
- 記録日タップで日別詳細へ遷移する。
- カテゴリ選択時は、該当カテゴリを含む日のみドット表示する。

#### グラフ

- 1画面に「総ボリューム」と「最大推定1RM」の2セクション。
- カードを入れ子にせず、セクション見出し + 単一surfaceとする。
- 軸ラベルと単位を必ず表示する。
- 選択点はRuleMark + PointMark + 値ラベルで示す。
- データ0件ではChartを描画せずEmptyStateを表示する。
- 色はカテゴリ色を系列識別に使用し、1系列ならprimaryまたはaccentを使う。

### 8.6 ワークアウト詳細

#### 目的

過去の1回分を確認し、編集または今日／任意の過去日へコピーする。

#### 仕様

- 日付と集計値を1つのサマリーsurfaceにまとめる。
- 種目別セット一覧は、種目ごとのセクションとして表示する。
- 主要操作は「記録を編集」。背景塗りつぶしのPrimaryButtonを使用する。
- 「今日のローテーションに使う」はSecondaryButtonにする。
- ボタン順は編集、コピー。両方とも確認ダイアログを維持する。
- コピーの確認ダイアログには「今日にコピーして開始」と「過去の日付を選んでコピー」の2択を置く。後者は月曜始まりの`DatePicker`（グラフィカルスタイル）をシートで表示し、未来日は選択不可にする。

### 8.7 種目ライブラリ

#### 目的

登録種目とPRを探し、カスタム種目を管理する。

#### 仕様

- Listとsearchableの標準挙動を維持する。
- カテゴリFilterChipを共通化する。
- 行は種目名、対象筋、PR、フォーム検索を表示する。
- PRがない場合は空欄とし、`0 kg`は表示しない。
- カスタムバッジは小さなsecondary fill + primary textとする。
- カスタム種目だけスワイプ削除を許可する既存ルールを維持する。

### 8.8 設定

#### 目的

単位変更とデータ管理を、標準設定画面として安全に提供する。

#### 仕様

- List / Section / segmented Pickerを維持する。
- 「あなたの記録」は3値を1つのMetricGroupとして最上部へ配置する。
- 統計値ごとの青・紫・インディゴは廃止し、primaryで統一する。
- アプリ情報は値をsecondaryで右寄せする。
- データ削除は最後のSectionに隔離し、destructive roleと確認ダイアログを維持する。
- バージョンは可能ならBundleから動的取得し、固定文字列を避ける。

## 9. アクセシビリティ要件

- すべての操作領域を最低44 x 44ptにする。
- Dynamic Typeは`.accessibilityExtraExtraExtraLarge`まで文字欠けなく表示する。
- 重要情報を色だけで区別しない。
- コントラストは通常文字4.5:1、大きな文字3:1以上を目標とする。
- アイコン単独ボタンにaccessibilityLabelと必要に応じてHintを設定する。
- 数値と単位はVoiceOverで自然に読める1要素へまとめる。例: 「72.5キログラム」。
- チップ、セグメント、タイマーは選択中・実行中の状態をaccessibilityValueで伝える。
- Reduce Motion、Increase Contrast、Button Shapesを有効にした状態を確認する。
- 横スクロールチップだけに依存せず、VoiceOverの順序を視覚順と一致させる。

## 10. 状態設計

各データ表示画面は最低限、次の状態を実装・確認する。

| 状態 | 表示 |
|---|---|
| Initial | 保存済みデータを反映した通常表示 |
| Empty | EmptyState + 次の操作 |
| Filtered Empty | 条件に一致しない旨 + フィルター解除導線 |
| Editing | 入力対象とキーボード操作が明確 |
| Disabled | 操作不可の理由が文脈上明確 |
| Destructive Confirmation | 対象と不可逆性を明記 |
| Success | 画面更新 + 必要最小限の触覚 |
| Error | データを失わず、再試行または閉じる手段を提示 |

ローカル処理が中心のため、常設ローディング表示は原則不要。将来同期機能を追加する場合は別仕様とする。

## 13. 総合受け入れ基準

### Visual

- 同じ役割のカード、ボタン、チップが全画面で同じ仕様になっている。
- ライト / ダークの両方で境界と文字が識別できる。
- 320pt、393pt、430pt幅で重なり、切れ、意図しない横スクロールがない。
- カードの入れ子がない。
- 主要操作は各画面で1つに見える。
- 日本語・英語・単位表記が本書のルールに統一されている。

### Functional

- 既存データが移行なしで表示される。
- 今日および過去日のワークアウトを作成・編集・削除できる。
- 種目追加、セット追加、重量・回数・メモ入力ができる。
- 休憩タイマーが開始・停止・時間変更できる。
- カテゴリ絞り込み、検索、グラフ表示が動作する。
- ワークアウトコピーとカスタム種目管理が動作する。
- kg / lbs切り替えが全関連画面へ反映される。

### Accessibility

- 主要フローをVoiceOverだけで完了できる。
- Accessibility最大文字サイズでも操作不能にならない。
- すべてのIconButtonが意味のある名前で読み上げられる。
- Reduce Motion有効時に不要なscale / springが抑制される。

### Quality

- Debug構成でビルドが成功する。
- 既存の保存・集計ロジックに回帰がない。
- Previewまたはスクリーンショットテストで主要状態を確認できる。
- 実装中に追加した共通UIへ、代表状態のPreviewが用意されている。

## 16. 実装時の判断ルール

本書に記載のない細部は、次の順序で判断する。

1. iOS標準コンポーネントの既定挙動
2. 本書の共通デザイントークンとコンポーネント
3. 同じ役割を持つ既実装画面のパターン
4. 操作回数が少なく、誤操作が起きにくい案

視覚的な派手さより、情報の読みやすさ、操作の一貫性、アクセシビリティを優先する。仕様から外れる必要がある場合は、理由と影響範囲を実装PRに明記する。
